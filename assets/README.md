# STARFALL — Asset Library

Единая библиотека всех игровых ресурсов. **Любые игровые ассеты размещаются только здесь**, а не в корне репозитория.

## Категории

| Каталог | Назначение | Правила |
|---|---|---|
| [ships/](ships/) | Корабли, истребители, транспорт, модели GLB | [README](ships/README.md), [GLB specification](ships/BLENDER_GLB_SPEC.md) |
| [droids/](droids/) | Дроиды и автономные боевые платформы | [README](droids/README.md) |
| [planets/](planets/) | Планеты, спутники, звёзды, поверхности и текстуры | [README](planets/README.md) |
| [weapons/](weapons/) | Вооружение, турели, снаряды и боевые ресурсы | [README](weapons/README.md) |
| [artifacts/](artifacts/) | Уникальные артефакты, предметы и сюжетные объекты | [README](artifacts/README.md) |

## Общие правила

1. Не создавать каталоги игровых ассетов в корне репозитория.
2. Каждому самостоятельному объекту назначать постоянный уникальный `id`; не переименовывать его после подключения без миграции ссылок.
3. Ресурсы объекта хранить вместе: `model.glb`, `config.json`, `README.md`, `textures/`, `animations/`, `preview.png` — по необходимости.
4. Общие для нескольких объектов материалы выносить на уровень категории, не дублировать без причины.
5. Каталоги категорий сохранять даже до появления первого ресурса; README служит точкой входа и фиксирует назначение.
6. При изменении структуры обновлять этот файл, корневой README, паспорт, мастер-инструкцию и CHANGELOG.

## Идентификаторы и группировка

Рекомендуемая структура: `<category>/<faction-or-type>/<asset_id>/`. Идентификатор — стабильный `snake_case` с порядковым суффиксом, например `pirate_fighter_003`. Не смешивать корабли и дроидов: принадлежность определяется игровым назначением объекта, а не только его внешним видом.
