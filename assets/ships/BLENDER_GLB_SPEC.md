# Технические требования к GLB-модели корабля (STARFALL)

Документ описывает только техническую сторону: оси, масштаб, топологию, материалы, текстуры, экспорт, проверку. Дизайн (форма, силуэт, число стволов и двигателей, цвета, детали) здесь не регламентируется и целиком остаётся за автором модели.

Контекст: игра STARFALL работает в браузере на Three.js r128 (ПК и iPhone). Модель кладётся в библиотеку `assets/ships/`, смотрится в `assets/ships/viewer.html`, позже подключается в игру. `STARFALL_CURRENT.html` при этом не меняется.

## 1. Оси и единицы (жёсткий контракт)

- 1 единица Blender = 1 метр. Рабочий размер задаёт автор; итоговый масштаб в игре подгоняется полем `scale` в `config.json`.
- **Нос корабля смотрит по +Y в Blender, корма по −Y, верх по +Z.** При экспорте с `export_yup=True` нос становится −Z, корма +Z, верх +Y, как ожидает игра.
- Начало координат (0,0,0) в центре корабля (`Object → Set Origin → Origin to Geometry`). Допустимое смещение центра габаритов от нуля — не более 5% длины.
- Перед экспортом у всех объектов: Rotation = (0,0,0), Scale = (1,1,1) (`Ctrl+A → All Transforms`).
- Положение корабля «в воздухе»: ни пола, ни подставок, ни фоновых объектов в сцене экспорта.

## 2. Геометрия

- **Бюджет: до 9 000 треугольников** на весь корабль (так сейчас в игре; ориентир для iPhone). Подсчёт после триангуляции. Если нужно больше, это отдельное решение.
- Без n-угольников (n-gons), висячих вершин и рёбер, дублей вершин, нулевых граней, перевёрнутых нормалей, невидимых внутренних граней.
- Все модификаторы применены (или `export_apply=True`), булевы операции доведены до чистой топологии.
- Нормали корректны после экспорта; гладкое затенение там, где нужно, жёсткие рёбра через `Mark Sharp`.
- Не больше **12 мешей-объектов**; имена латиницей без суффиксов `.001`. Рекомендуется слить мелочь в логические части (корпус, крылья, кабина и т.п.), чтобы не плодить draw calls.
- Скелет, шейпкиты, анимации не нужны (игра сама двигает части, если надо).

## 3. Материалы

- Только Principled BSDF (metallic-roughness). Не больше **3 материалов** на корабль (идеально 1–2): меньше материалов, меньше draw calls на iPhone.
- Прозрачность (стекло и т.п.) только alpha blend; такой материал держать отдельным и малым по площади.
- Эмиссия (светящиеся элементы) через Emissive материала, а не через лампы: источники света при экспорте отбрасываются.
- Никаких процедурных узлов (Noise, Voronoi и т.п.) в итоговом материале: экспортёр glTF их не переносит. Всё процедурное запекается в изображения.

## 4. Развёртка и текстуры

- UV обязательна. Один атлас на материал; островки без перекрытий (зеркальные половины можно перекрывать), все UV внутри 0–1, отступ между островками не меньше 8 px при 1024 px.
- Набор текстур (все по необходимости, минимально Base Color):
  - **Base Color** — sRGB; JPEG качество ~85.
  - **Normal** — OpenGL-стиль (Y+), Non-Color; PNG.
  - **ORM** — одно изображение: R = Ambient Occlusion, G = Roughness, B = Metallic; Non-Color; PNG.
  - **Emissive** — sRGB; JPEG ~85.
- Размер каждой текстуры: рекомендуется 1024×1024, **максимум 2048**; степень двойки. Лучше квадрат.
- Запекание: Cycles, 64–128 сэмплов. Затем изображения подключаются к материалу так, чтобы экспортёр упаковал каналы корректно (узел `glTF Material Output` в Blender 4.x, `glTF Settings` в 3.x для Occlusion).
- Текстуры не должны отличаться от цвета в Blender из-за цветового пространства: Base Color/Emissive — sRGB, остальные — Non-Color.

## 5. Метки (по желанию)

Если на корабле есть места, где игра должна что-то включать (пламя двигателя, вспышки выстрелов и т.п.), автор ставит пустышки Empty с понятными именами. Сколько их и где решает автор. Соглашение об именах: `ENG_0`, `ENG_1` … для двигателей, `GUN_0` … для стволов, `COCKPIT` для кабины. Ось +Y пустышки смотрит «наружу» (для двигателя назад, для ствола вперёд). Если у метки нужны параметры, они задаются в Custom Properties (экспортируются как `extras`). Без меток корабль тоже проходит приёмку.

## 6. Параметры экспорта

```python
bpy.ops.export_scene.gltf(
    filepath=out_path, export_format='GLB',
    export_yup=True, export_apply=True,
    use_selection=False, export_cameras=False, export_lights=False,
    export_extras=True, export_animations=False, export_skins=False,
    export_morph=False, export_texcoords=True, export_normals=True,
    export_tangents=False, export_image_format='AUTO',
    export_materials='EXPORT',
    export_draco_mesh_compression_enable=False)
```

Имена параметров зависят от версии Blender (например, для цветов вершин в 4.2 появился `export_vertex_color`, раньше был `export_colors`). Сверяйте с установленной версией: `bpy.ops.export_scene.gltf.get_rna_type().properties.keys()`. Вручную: `File → Export → glTF 2.0 (.glb)` с теми же настройками (Format: GLB, +Y Up, Apply Modifiers, Custom Properties, без Cameras/Lights/Animation). Draco по умолчанию выключен (игре на первом этапе проще без него).

**Размер файла: до 5 МБ**, лучше до 2 МБ. Больше: уменьшить текстуры или включить Draco (тогда игре понадобится DRACOLoader).

## 7. Проверка перед коммитом

1. `python3 -m http.server` в корне репозитория → `http://localhost:8000/assets/ships/viewer.html?ship=<id>`.
2. В просмотрщике нет красных пунктов: треугольники ≤ 9 000, текстуры ≤ 2048 px, файл ≤ 5 МБ.
3. Включить «Оси» и убедиться, что нос корабля смотрит в −Z (стрелка Z показывает «на тебя» с кормы), центр модели у начала координат.
4. Посмотреть модель с разных видов и в трёх вариантах света: нет чёрных пятен (битые нормали), швов на текстурах, торчащих деталей.
5. Опционально: `npx gltf-validator model.glb` без ошибок.

## 8. Что сдавать

В папку `assets/ships/<фракция>/<id>/` (`id` вида `фракция_класс_NNN`):
- `model.glb`
- `config.json` по шаблону `assets/ships/_template/config.json`
- `README.md` корабля (замысел в паре строк, версия Blender, итог проверки)
- (по желанию) `preview.png`

Плюс запись в `assets/ships/catalog.json` со `status: "glb"`. `.blend` в репозиторий не класть, если он больше 10 МБ.

## 9. Приёмка

- [ ] Нос в −Z (в GLB), верх +Y, начало координат у центра, Transforms применены.
- [ ] Треугольников ≤ 9 000, материалов ≤ 3, мешей ≤ 12, нет n-gons и мусорной геометрии.
- [ ] Текстуры: UV 0–1 без перекрытий, размер ≤ 2048, ORM упакован как R/G/B = AO/Rough/Metal.
- [ ] Файл ≤ 5 МБ, открывается в `viewer.html` без красных пунктов.
- [ ] Папка корабля, `config.json`, запись в `catalog.json` на месте; `STARFALL_CURRENT.html` не менялся.
