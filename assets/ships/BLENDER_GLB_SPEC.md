# ТЗ: GLB-модель корабля для STARFALL (Blender → glTF)

Этот документ отдаётся исполнителю (человек или ИИ-агент) целиком. Раздел 12 — бриф конкретного корабля, он заполняется отдельно для каждой модели. Всё остальное — общие требования для любого корабля.

## 1. Цель и контекст

Построить 3D-модель космического корабля в Blender и выдать её как `model.glb` для игры STARFALL (браузерная космическая игра на Three.js r128, ПК и iPhone). Модель сначала живёт в библиотеке `assets/ships/` и просматривается в `assets/ships/viewer.html`; позже её подключат в игру. Игровой файл `STARFALL_CURRENT.html` не трогать.

Игра: тёмный космос, неоновые акценты. Корабль игрока — бирюзовые акценты, пираты — оранжевые и ржавые, награды — золотые. Камера в игре третьего лица, корабль виден сзади и сверху на расстоянии, поэтому решают силуэт, цвет и свечение двигателей. Мелкая детализация почти не видна.

## 2. Что должно быть сдано

1. `build_<id>.py` — Python-скрипт для Blender (`bpy`), который с нуля строит корабль, назначает материалы, запекает текстуры, проверяет себя и экспортирует GLB. Запуск без интерфейса: `blender -b -P build_<id>.py -- --out <папка>`. Скрипт идемпотентный: повторный запуск даёт тот же результат.
2. `model.glb` — результат экспорта.
3. `config.json` — паспорт по шаблону `assets/ships/_template/config.json`.
4. `preview.png` — рендер 1024×576, три четверти спереди-сверху на тёмном фоне.
5. `README.md` корабля: замысел, статус, как пересобрать, итог проверки.
6. `.blend` не коммитить, если больше 10 МБ (источник — скрипт).

Папка корабля: `assets/ships/<фракция>/<id>/`, где `id` вида `фракция_класс_NNN` (например `pirate_raider_001`). Запись в `assets/ships/catalog.json` со `status: "glb"`.

## 3. Система координат (жёсткий контракт)

- Единицы: 1 Blender-единица = 1 метр. Начальная длина по классам (корректируется в брифе): истребитель 8–12 м, тяжёлый 14–20 м, грузовой 30–60 м, крейсер 60–120 м. В игре итоговый размер задаётся полем `scale` в `config.json`.
- **Нос корабля смотрит по +Y Blender, двигатели сзади по −Y, верх по +Z.** После экспорта с `export_yup=True` нос окажется в −Z glTF, двигатели в +Z, верх в +Y. Это ожидает игра.
- Начало координат (0,0,0) в геометрическом центре корпуса; корабль симметричен относительно плоскости X=0 (зеркало по X, где возможно: `Mirror`-модификатор, потом Apply).
- Перед экспортом: у всех объектов Rotation = (0,0,0), Scale = (1,1,1) (Apply All Transforms), родитель только у вспомогательных пустышек.

## 4. Геометрия

- Бюджет: **не больше 9 000 треугольников** на весь корабль (после триангуляции экспортёра), ориентир 5 000–7 000. Крупные классы — по согласованию в брифе.
- Строить параметрически: корпус как лофт по сечениям (суперэллипс с переменной степенью) или из примитивов с `Bevel`/`Subdivision`; крылья и пластины как отдельные меши. Все размеры и числа вынести в словарь `PARAMS` в начале скрипта. Параметр `seed` для вариаций (если нужны).
- Запрещено: n-угольники (n-gons) на финальном меше, висячие вершины и рёбра, дубликаты вершин, перевёрнутые нормали, внутренние невидимые грани, объекты «под полом» и за пределами корпуса, неприменённые модификаторы, булевы операции с «грязной» топологией.
- Нормали: Shade Smooth с Auto Smooth/Weighted Normal там, где нужна гладкость; жёсткие рёбра (`Mark Sharp`) для панелей и стыков. Нормали должны быть корректны после экспорта.
- Объектов-мешей не больше 12 (слияние в логические части: `hull`, `wing_L`, `wing_R`, `engine_L`, `engine_R`, `cockpit`, `details`). Имена латиницей, без «.001».
- Скелет, шейпкиты, анимации: не нужны. Вращения винтов и пр. игра делает сама.

## 5. Обязательные точки (пустышки, Empty)

Пустышки-метки экспортируются как узлы glTF с позицией; игра по имени находит места эффектов. Положение — в центре соответствующей детали, ось +Y пустышки направлена «наружу» (для двигателя назад, для пушки вперёд).

- `ENG_0`, `ENG_1`, … — центры сопел двигателей (по одной на сопло).
- `GUN_0`, `GUN_1`, … — дула орудий (по числу стволов корабля; число стволов указано в брифе).
- `COCKPIT` — центр кабины.
- `NAV_L` / `NAV_R` — навигационные огни (по желанию).

В каждой метке в Custom Properties можно задать `size` (число, радиус эффекта в метрах); экспорт с `export_extras=True`.

## 6. Материалы и текстуры

- Модель материалов — Principled BSDF (metallic-roughness). Не больше **3 материалов** на корабль (идеально 1–2): корпус, эмиссия (окна и двигатели), стекло кабины (прозрачный, alpha blend).
- Текстуры: Base Color (sRGB), Normal (OpenGL-стиль, Y+; в Blender Normal Map-узел даёт то, что нужно), ORM в одном изображении (R = Ambient Occlusion, G = Roughness, B = Metallic), Emissive (sRGB). Размер до 2048 px, рекомендуется 1024. Формат: JPEG для Base Color и Emissive (качество 85), PNG для Normal и ORM.
- Развёртка (UV) обязательна: один атлас на материал, без перекрытий (кроме зеркальных частей, где допустимо), отступ между островками ≥ 8 px при 1024 px. Все UV внутри 0–1.
- Запекание (Bake, Cycles, 64–128 сэмплов): AO и цвет панелей/потёртостей из высокополигональных деталей или процедурных текстур Blender в атлас. Скрипт запекает и сохраняет изображения в `textures/`, затем подключает их к материалу так, чтобы экспортёр glTF упаковал каналы корректно (узел `glTF Material Output` / `glTF Settings` для Occlusion).
- Цветовая схема из брифа: основа тёмная (корпус не должен сливаться с тёмным космосом, но и не «белить»), акценты неоном, эмиссия не больше 3 цветовых зон. Свечение двигателей делается эмиссивным материалом, не светом.
- Запрещены: процедурные узлы шума в материале на экспорте (их экспортёр не переносит), все текстуры должны быть запечены в изображения.

## 7. Параметры экспорта (точно)

```python
bpy.ops.export_scene.gltf(
    filepath=out_path, export_format='GLB',
    export_yup=True, export_apply=True,
    use_selection=False, export_cameras=False, export_lights=False,
    export_extras=True, export_animations=False, export_skins=False,
    export_morph=False, export_texcoords=True, export_normals=True,
    export_tangents=False, export_vertex_color='NONE',
    export_image_format='AUTO', export_materials='EXPORT',
    export_draco_mesh_compression_enable=False)
```

Имена параметров экспортёра зависят от версии Blender (например, `export_vertex_color` появился в 4.2, раньше был `export_colors`; узел материала называется `glTF Settings` в 3.x и `glTF Material Output` в 4.x). Исполнитель обязан сверить их с установленной версией (`bpy.ops.export_scene.gltf.get_rna_type().properties.keys()`) и написать в README, какая версия использовалась.

Draco по умолчанию **выключен** (игре на первом этапе проще без него). Размер файла: до 5 МБ, лучше до 2 МБ.

## 8. Самопроверка в скрипте (перед экспортом и после)

Скрипт должен вывести отчёт и завершиться с кодом ≠ 0, если проверка не пройдена:

1. Число треугольников ≤ бюджета.
2. Нет n-gon, нет некорректных/нулевых граней, нет не связанных вершин.
3. Все Transforms применены, начало координат у центра (смещение центра габаритов ≤ 5% длины).
4. Габариты: длина вдоль Y — наибольший размер (для кораблей с вытянутым корпусом); нос действительно в +Y: центр масс вершин передней трети по Y лежит с положительной стороны, и самая «острая» часть (минимальное сечение) спереди — либо заданное в брифе.
5. Симметрия X: для каждой вершины есть зеркальная (допуск 1 мм), кроме объектов, помеченных в брифе как асимметричные.
6. Все UV в 0–1, перекрытий нет (кроме зеркальных).
7. Есть все обязательные пустышки (`ENG_*` не меньше, чем указано в брифе, `GUN_*` по числу стволов, `COCKPIT`).
8. После экспорта: GLB открывается, размер ≤ 5 МБ, текстуры ≤ 2048 px.
9. По возможности: `npx gltf-validator model.glb` без ошибок (предупреждения допускаются).

## 9. Проверка в просмотрщике

После экспорта: открыть `assets/ships/viewer.html?ship=<id>` (локальный сервер, например `python3 -m http.server`) и убедиться, что красных пунктов проверки нет, в режиме «Оси» нос смотрит в −Z, а центр модели у начала координат. Приложить скриншот или итог проверки в README корабля.

## 10. Критерии приёмки

- [ ] `build_<id>.py` пересобирает модель одной командой, отчёт самопроверки без ошибок.
- [ ] Треугольников ≤ 9 000, материалов ≤ 3, текстуры ≤ 2048 px, файл ≤ 5 МБ.
- [ ] Нос в −Z (в GLB), двигатели в +Z, все метки `ENG_*`, `GUN_*`, `COCKPIT` на месте.
- [ ] Силуэт читается с расстояния и сверху/сзади (вид из игровой камеры), цвета по палитре брифа.
- [ ] В просмотрщике нет красных пунктов, превью `preview.png` приложено.
- [ ] В репозитории: папка корабля, `catalog.json`, `config.json`, README. `STARFALL_CURRENT.html` не менялся.

## 11. Порядок работы исполнителя

1. Прочитать этот документ и бриф (раздел 12). Если в брифе чего-то не хватает, выбрать разумное значение по умолчанию и записать его в README корабля (не останавливаться).
2. Написать скрипт, запустить, посмотреть превью, итеративно править силуэт (не больше 3 итераций на согласование с заказчиком по скриншотам).
3. Прогнать самопроверку и просмотрщик, оформить README, закоммитить: `assets: <id> — модель корабля`.

## 12. Бриф корабля (заполняется под каждую модель)

| Поле | Значение |
|---|---|
| `id` | |
| Название | |
| Фракция / класс | player / pirate / trader …; fighter / interceptor / heavy / gunship / freighter / cruiser / boss |

| Длина, м | |
| Число стволов / двигателей | |

| Палитра | основной / вторичный / акцент / свечение |
