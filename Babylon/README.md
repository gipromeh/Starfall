# STARFALL — Babylon migration workspace

**Статус:** изолированное направление разработки, не production-сборка.  
**Базовая версия исходной игры:** v85.  
**Репозиторий:** [gipromeh/Starfall](https://github.com/gipromeh/Starfall), ветка `main`.

## Назначение

Каталог `Babylon/` — отдельная рабочая область для поэтапного переноса STARFALL с Three.js на Babylon.js и развития игровых подсистем. Здесь хранятся применимые инструкции, архитектура, спецификации, план миграции и отдельные тесты новой реализации.

## Важное разделение

- Корневая `STARFALL_CURRENT.html` v85 остаётся действующей production-версией и контрольным источником поведения.
- Корневые `STARFALL_MASTER_INSTRUCTION.yaml`, `STARFALL_PASSPORT.md`, `CHANGELOG.md` и `CLAUDE.md` продолжают действовать для основной игры.
- Документы в `Babylon/` дополняют корневые правила только для Babylon-направления. При конфликте запрещено молча менять production-игру: сначала зафиксировать расхождение и согласовать переход.
- Старые файлы `STARFALL_Babylon_Rebuild.html`, `STARFALL_Babylon_Migration.html`, `STARFALL_Babylon_Equivalence.html` из чатов — экспериментальные артефакты, не источник истины. Они не заменяют v85 и не считаются функционально эквивалентными.
- До прохождения матрицы приёмки Babylon-сборка не подменяет GitHub Pages и корневую игру.

## Правило коммитов

Пока ведётся миграция, изменения Babylon-направления коммитятся в `main` только внутри `Babylon/` (плюс при необходимости отдельные CI-файлы для тестов Babylon). Корневую игру, её паспорт, CHANGELOG и опубликованную версию не менять в рамках Babylon-коммита, если задача прямо не требует переключения production.

Каждый коммит должен содержать завершённый небольшой этап, обновлённые документы и проверяемый результат. Рекомендуемый формат: `Babylon: этап N — краткое описание`.

Когда Babylon-версия достигнет полной функциональной эквивалентности, будет отдельное решение о её интеграции в корень и обновлении корневого паспорта, CHANGELOG, инструкций и GitHub Pages.

## Текущая точка

Создана только документационная структура. Игровой код в репозитории не переносился и не изменялся. Следующая реализация должна начинаться с актуальной корневой v85, а не с экспериментального HTML из предыдущих чатов.
