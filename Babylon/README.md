# STARFALL — Babylon migration workspace

**Статус:** изолированная исполняемая Babylon-сборка; не production и не parity release.  
**Базовая версия исходной игры:** v85.  
**Репозиторий:** [gipromeh/Starfall](https://github.com/gipromeh/Starfall), ветка `main`.

## Назначение

Каталог `Babylon/` — отдельная рабочая область для поэтапного переноса STARFALL с Three.js на Babylon.js и развития игровых подсистем. Здесь находятся инструкции, архитектура, спецификации, исполняемая сборка, тесты и план миграции.

## Запуск

Опубликованная страница: [STARFALL Babylon](https://gipromeh.github.io/Starfall/Babylon/).

Локальный запуск из корня репозитория:

```bash
python3 -m http.server 8000
```

Открыть `http://localhost:8000/Babylon/`. Не запускать через `file://`: GLB и ES-модули требуют HTTP origin.

Зависимости Babylon.js 7.0 и glTF loader подключены с фиксированной версией через официальный CDN; Yuka загружается как ES-модуль. Для запуска нужен доступ к сети.

## Управление текущего боевого среза

- W / S — тяга вперёд / назад.
- A / D — боковой стрейф.
- R / C — вертикальный манёвр.
- Q / Z — крен.
- Мышь — поворот/прицеливание; начальное движение указателя после старта игнорируется.
- ЛКМ — лазер; ПКМ / F / Пробел — самонаводящаяся ракета.
- Shift — форсаж; X — торможение.
- Esc / P — пауза; F3 — диагностика.
- На сенсорном экране: виртуальный джойстик, FIRE, MISSILE, BOOST.

## Текущее состояние B1

Реализованы:
- Babylon.js Engine/Scene, chase camera, resize и обработка потери WebGL context.
- Звёздное поле, планета, станция и процедурный корабль игрока.
- Загрузка существующего `pirate_droid_001.glb`; статическая геометрия объединяется в группы по материалам, чтобы сократить draw calls.
- Инерционная FlightModel; Yuka Seek steering передаёт управляющее воздействие через FlightModel противника.
- Лазерные и самонаводящиеся снаряды, swept segment/sphere collision, урон щиту/корпусу, уничтожение цели, награда и повторное появление противника.
- HUD, мобильные touch controls, отдельное сохранение `sf_babylon_slice`.
- Чтение существующих v85 SAVE 2.0 / legacy `sf_sv` без записи в исходные слоты.

Chromium CI: **7/7 Playwright tests PASS**. Проверяются запуск сцены, WebGL canvas, начальное направление корабля, загрузка оптимизированной GLB-модели, разгон, уничтожение/возрождение противника, реальное попадание ракеты и мобильный HUD.

CI использует headless Chromium со SwiftShader. Это функциональная проверка, а не репрезентативный GPU/FPS benchmark. Реальный iPhone Safari ещё не тестировался.

## Известные ограничения

Это боевой технический срез, а не перенос всей игры. Ещё не перенесены полная экономика, торговля, пять систем, трафик, станционные сервисы, диалоги, контракты, сюжетные цепочки и весь контент v85. Коллизии текущего среза используют swept analytic adapter; Havok пока не является авторитетным физическим решателем. До отдельного аудита SAVE 2.0 совместимость не считать полной.

## Важное разделение

- Корневая `STARFALL_CURRENT.html` v85 остаётся действующей production-версией и контрольным источником поведения.
- Корневые `STARFALL_MASTER_INSTRUCTION.yaml`, `STARFALL_PASSPORT.md`, `CHANGELOG.md` и `CLAUDE.md` продолжают действовать для основной игры.
- Документы в `Babylon/` дополняют корневые правила только для Babylon-направления. При конфликте запрещено молча менять production-игру: сначала зафиксировать расхождение и согласовать переход.
- Старые файлы `STARFALL_Babylon_Rebuild.html`, `STARFALL_Babylon_Migration.html`, `STARFALL_Babylon_Equivalence.html` из чатов — экспериментальные артефакты, не источник истины.
- До прохождения полной матрицы приёмки Babylon-сборка не подменяет корневую игру.

## Правило коммитов

Пока ведётся миграция, изменения Babylon-направления коммитятся в `main` только внутри `Babylon/` (плюс отдельные CI-файлы для тестов Babylon). Корневую игру, её паспорт, CHANGELOG и опубликованную production-версию не менять в рамках Babylon-коммита.

Когда Babylon-версия достигнет полной функциональной эквивалентности, будет отдельное решение о её интеграции в корень и обновлении корневого паспорта, CHANGELOG, инструкций и GitHub Pages.
