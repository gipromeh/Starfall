# STARFALL — план полной верификации игровых механик

**Рабочая ветка:** `lab/elite-combat-ai`  
**Production:** `main` — не изменять в рамках лабораторной проверки.  
**Версия:** v90, `STARFALL_CURRENT.html`.  
**Статус:** аудит покрытия; полная приёмка ещё не достигнута.

## 1. Цель

Подтвердить воспроизводимыми тестами весь цикл: запуск → станция → вылет → полёт/исследование → бой/добыча/торговля → награда → возвращение → покупка/модернизация → сохранение → продолжение. Зелёный CI сам по себе не означает завершённую игру: тест должен проверять поведение, инвариант или измеряемый критерий, а не только наличие строки в HTML.

## 3. Открытые пробелы

1. **Полёт:** нет полного детерминированного набора по инерции, разгону/торможению, pitch/yaw/roll, strafe, boost и зависимости результата от временного шага.
2. **Оружие:** production batch пока в основном проверяет лазерный огонь по стартовой эскадрилье. Отдельно нужны ракеты, захват цели, боезапас, cooldown/heat, попадания и ядерное оружие.
3. **Полный бой:** нужны реальные сценарии E/E2, эскадрильи, типов NPC, босса, численного превосходства, уклонения, смерти и респавна; проверять переходы FSM, а не наличие названий состояний.
4. **Навигация/мир:** сквозные проверки выбора цели, переходов секторов, орбитальных объектов, стыковки и очистки временных объектов.
5. **Радар:** статическая проверка не доказывает корректное движение контактов и их удаление после уничтожения/перехода.
6. **Экономика/прогресс:** связать фактические характеристики после апгрейдов с поведением корабля; проверить длительный цикл «рейс → награда → покупка → следующий рейс».
7. **Графика/мобильность:** нужны повторяемые замеры frame time, draw calls, памяти и GPU-ресурсов. Headless не даёт достоверной производительности физического iPhone.

## 4. Этапы приёмки

### Gate A — сборка и запуск
- Все inline scripts проходят синтаксическую проверку.
- Все quick checks проходят.
- Игра и WebGL инициализируются без необработанных исключений.
- Проверяются переходы menu → dock → play и базовый reset.

### Gate B — полёт и управление
- Проверить menu/dock/play/dying/restart.
- Инерция после отпускания управления, разгон, торможение, вращение по трём осям, все strafe-направления.
- Boost: заряд/топливо, восстановление и обратная связь.
- Сравнить физику при 30/60/120 Hz и переменном `dt`.
- Проверить keyboard/mouse/touch и отсутствие конфликтов ввода.

### Gate C — оружие и бой
- Для обычных пиратов и стартовой эскадрильи проверять общий Elite-derived ATTACK/EVADE pilot: OCS-компоненты, реакцию на близость и входящий снаряд, возврат к атаке после разрыва дистанции, непрерывную инерционную интеграцию и отсутствие старых scripted-waypoint состояний.
- Boss-specific movement учитывать как отдельный тип поведения; не смешивать его приёмку с обычными NPC.
- Лазерные hardpoints, направление, скорость, cooldown/heat, очистка снарядов.
- Ракеты: выбор/захват → запуск → полёт → попадание/промах → расход боезапаса.
- Ядерное оружие: радиус поражения, эффекты и стоимость по производительности.
- Щит, корпус, смерть, восстановление.
- Все классы NPC и реальные переходы боевого FSM.
- Столкновения корабль-корабль и снаряд-корабль.
- Seeded batches с разными дистанциями, ориентациями, скоростями и составами групп.

### Gate D — мир, станции, экономика
- Сквозной рейс: вылет → цель → взаимодействие → возвращение → стыковка.
- Переходы секторов и очистка временных объектов.
- Рынок, покупка/продажа груза, ремонт, оборудование, корабли и применение улучшений.
- Контракты/награды, bounty, репутация, фракционные последствия, отсутствие повторного начисления.
- Deep Space события, цепочки, выбор исхода и сохранение.

### Gate E — сохранения и восстановление
- Сохранение после покупки, продажи, апгрейда, награды, перехода и смерти.
- Перезапуск и полное восстановление runtime-состояния.
- Миграции, повреждение основного/резервного слота, rollback, отказ хранилища.
- Нет потери или дублирования валюты, груза и наград.

### Gate F — мобильность, графика, устойчивость
- Chromium/WebKit mobile emulation: запуск, touch, ориентация, размеры элементов, safe areas, фон/возврат вкладки.
- Сцены: станция, планеты, астероиды, бой, взрыв, плотная группа NPC.
- Замеры frame time, dropped frames, draw calls, geometries/textures/programs и длительности сессии.
- Soak-тест: повторные вылеты, бои, уничтожения, стыковки и переходы без накопления ресурсов.
- Физический iPhone помечать как не проверенный, если нет удалённого устройства.

## 5. Правила batch-тестов
- Только production-функции и production collision/damage path; абстрактная модель — только для исследований, не для балансировочной приёмки.
- Каждый сценарий имеет фиксированный seed.
- Начинать с коротких smoke batches; увеличивать число боёв после замера времени и стабильности runner.
- Отчёт: параметры сценария, выстрелы/попадания, нанесённый/полученный урон, TTK, выживаемость, FSM-состояния, численная устойчивость.
- Не подбирать параметры под желаемый процент побед; критерии фиксировать до эксперимента.
- NaN/Infinity, зависание FSM, потеря цели/снаряда, утечки или невоспроизводимый одинаковый seed — провал.

## 6. Критерии финализации
Механика принята только если есть поведенческий тест, он запускается в Actions, воспроизводим по seed, покрывает нормальный/граничный путь и сброс/восстановление, не ломает связанные системы, а паспорт фиксирует реализацию, параметры, ограничения, Elite-основание (если применимо) и имя теста.

Игра считается прошедшей финализацию только после Gate A–F. До этого статусы отдельных систем: `verified`, `partial`, `not-tested`. Не заявлять «всё протестировано» по одному зелёному workflow.

## 7. Production combat baseline

Последний подтверждённый запуск: run `41421811411`, commit `eb20925ba4ff6b618943ee65bfcd3debc4095233`.

- 12 seeded trials × 20 секунд; реальный production `upd(dt)` и collision/damage pipeline.
- 1 824 выстрела игрока; 892 выстрела противника.
- 42 события урона по противникам; 701.82 суммарного урона.
- 20 событий попадания по игроку; 104 суммарного урона.
- 0 смертей игрока; 0 полных уничтожений двухкорабельной группы.

Это smoke baseline со стационарным игроком, не доказательство общего баланса или завершённости боя.

## 8. Ограничения
- Playwright Chromium/WebKit не равен реальному Safari на физическом iPhone.
- Headless WebGL/SwiftShader не измеряет достоверно FPS конкретного GPU iPhone.
- Production HTML не менять ради тестов; диагностические hooks добавлять точечно и отдельно регрессировать.
