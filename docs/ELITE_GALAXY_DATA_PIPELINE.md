# STARFALL — полный массив галактики Elite Dangerous

## Решение

Используется полный Spansh Galaxy Dump, а не облегчённый срез. Исходный архив, SQLite-хранилище и любые производные индексы являются внешними данными и **не входят в Git, GitHub Pages или клиентский bundle**.

Spansh публикует whole-galaxy наборы систем, тел и станций. EDDN отдельно предупреждает, что полный `galaxy.json.gz` очень велик и является единственным указанным источником полного набора всех известных тел. Фактическую дату генерации, URL, размер и доступность нужно проверять на странице источника перед каждым обновлением.

Источник: https://www.spansh.co.uk/dumps  
Описание полноты и ограничений: https://github.com/EDCD/EDDN#archives-and-data-dumps

## Компоненты

- `tools/elite_galaxy.py` — загрузка с докачкой, потоковый импорт и пространственный запрос.
- `requirements-data.txt` — отдельная зависимость `ijson`; она не добавляется в runtime игры.
- `data/elite-dangerous/raw/galaxy.json.gz` — исходный архив.
- `data/elite-dangerous/store/galaxy.sqlite3` — локальная база с полным JSON payload каждой системы.
- Пространственная ячейка — 128 ly по каждой оси; координаты сохраняются без округления.
- Основной ключ `id64` хранится как TEXT, чтобы не зависеть от знакового диапазона SQLite INTEGER.
- В таблице есть индексы по сектору и имени. Детали тел, станций, фракций, рынков и прочих полей сохраняются целиком в `payload`, а не теряются при нормализации базовых координат.

## Установка и запуск

Требуется Python 3.10+ и достаточно свободного места под архив, распаковку/чтение и базу данных. Объём БД может быть сопоставим или больше распакованного JSON; заранее зарезервируйте место на отдельном SSD.

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-data.txt

# Скопируйте актуальную ссылку galaxy.json.gz со страницы Spansh Dumps:
python tools/elite_galaxy.py download --url "ВСТАВЬТЕ_АКТУАЛЬНЫЙ_URL"

# Потоковый импорт: весь JSON-массив не загружается в RAM.
python tools/elite_galaxy.py import

# Пример пространственного запроса (Sol около 0,0,0):
python tools/elite_galaxy.py near --x 0 --y 0 --z 0 --radius 100 --limit 100
```

Для нестандартного размещения используйте `--output`, `--source` и `--database`. Загрузка пишет во временный `.part`, поддерживает HTTP Range при наличии поддержки сервером и создаёт SHA-256 sidecar. При прерывании повторите ту же команду. Импорт читает gzip-поток и обрабатывает по одной записи; транзакции фиксируются пакетами, размер пакета настраивается через `--batch-size`.

## Формат хранения и дальнейшая интеграция

SQLite — локальный ingestion/index store, не формат доставки в браузер. Клиент STARFALL не должен открывать полную базу или получать её целиком.

Следующий интеграционный слой должен публиковать только компактные read-only shard-файлы/ответы по области интереса:
1. Поиск ближайших систем — пространственный запрос по секторным индексам.
2. При выборе системы — загрузка её сохранённого JSON payload с телами и станциями.
3. Для маршрута — запрос коридора/набора секторов, а не всей галактики.
4. Кэшировать загруженные сектора ограниченным LRU и выгружать удалённые; не держать всю галактику в памяти iPhone.
5. Сервис выдачи данных разворачивать отдельно от GitHub Pages. Публичные данные не должны блокировать загрузку игрового HTML.

Не подключать БД к `starfall.html` напрямую и не менять существующие полёт, бой, радар, экономику и SAVE в рамках импорта данных.

## Ограничения текущего этапа

- Скрипт создаёт локальное полное хранилище и пространственный индекс, но ещё не публикует HTTP API и не подключает галактику к игровому HUD/навигации.
- Импорт можно безопасно повторить: строки с тем же `id64` обновляются. При аварии уже зафиксированные пакеты останутся в базе; повторный импорт переобработает источник целиком.
- Перед запуском полного импорта необходимо проверить актуальную ссылку/дату dump на Spansh. Не зашивать изменяемые URL и размеры в код.
- Проверка на полном архиве не выполнялась; корректность импорта следует сначала подтвердить на небольшом тестовом JSON-массиве и затем на полном dump с контролем количества прочитанных/пропущенных записей.
